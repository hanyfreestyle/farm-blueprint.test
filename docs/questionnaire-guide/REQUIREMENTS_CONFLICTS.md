# Requirements Conflicts

هذا الملف مخصص لتسجيل **التعارضات الحقيقية غير المحسومة** التي يكتشفها وكيل كتابة الـRequirements عند مقارنة دليل التفسير مع ملف الإجابات النهائي.

وجود تعارض هنا يعني أن الوكيل **لا يملك صلاحية حسم النقطة بنفسه**.

---

## قواعد الاستخدام

1. يسجل كل تعارض بكود فريد.
2. يجب ذكر `Question Key` لكل سؤال مرتبط بالتعارض.
3. يشرح التعارض بصورة محايدة دون اقتراح قرار على أنه معتمد.
4. يحدد الجزء المتأثر الذي لا يمكن حسمه قبل القرار.
5. يكتب سؤالًا واضحًا يحتاج إجابة من صاحب المشروع.
6. يستمر الوكيل في كتابة الأجزاء غير المتأثرة بالتعارض.
7. بعد صدور القرار البشري، يتم تحديث الـRequirement المتأثر والتحقق من زوال التعارض.
8. بعد زوال التعارض، تحذف الملاحظة المفتوحة من هذا الملف. يحتفظ Git بتاريخها عند الحاجة للمراجعة.
9. لا يستخدم `تصور_مشروع_الارانب.md` لحسم التعارضات في مرحلة كتابة الـRequirements.

---

## نظام الأكواد

```text
RQ-CF-MD-0001   إدارة البيانات الأساسية / Master Data
RQ-CF-OPS-0001  إعدادات التشغيل / Operation Settings
RQ-CF-HERD-0001 تكوين وإدخال القطيع / Herd Setup
RQ-CF-WF-0001   الحركات ودورة التشغيل / Workflow
RQ-CF-RPT-0001  التقارير ومؤشرات الأداء / Reports
```

يزداد الرقم داخل كل مجموعة بالتتابع.

---

## قالب تسجيل التعارض

```md
## RQ-CF-MD-0001

Status: Open

Section: إدارة البيانات الأساسية
Subsection: اسم القسم الفرعي

Related Question Keys:
- entity.question_key_a
- entity.question_key_b

Conflict:
وصف دقيق للتعارض بين القرارين أو الإجابتين.

Impact:
ما الجزء الذي لا يمكن حسمه بصورة صحيحة قبل حل التعارض.

Required Decision:
السؤال المحدد المطلوب من صاحب المشروع حسمه.
```

## التعارضات المفتوحة حاليًا

لا توجد تعارضات مفتوحة مسجلة حاليًا.
